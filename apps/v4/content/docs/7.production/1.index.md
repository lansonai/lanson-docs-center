# Production Checklist

Use this list before a production cutover.

## Credentials & authentication

- [ ] API keys are stored **server-side only** — never shipped in frontend bundles or URLs.
- [ ] Browser clients obtain a short-lived session token (`rt_…`, 60 s) from your backend instead of using the long-lived key. See [Authentication](/docs/start/authentication).
- [ ] Keys can be rotated / revoked without a redeploy.

## Connection handling

- [ ] Your client handles the relevant close codes — `4408` (idle), `1008` (session limit), `1011` (socket error). See [Connection Lifecycle](/docs/realtime/connection-lifecycle).
- [ ] Reconnect uses capped exponential backoff and resets on success. See [Reconnection & Retries](/docs/production/reconnection-retries).
- [ ] `session.update` is re-sent after every reconnect (sessions do not resume).

## Limits

- [ ] Client honours HTTP `429` with `Retry-After`.
- [ ] Audio frames stay below 1 MiB.
- [ ] You understand the per-plan limits (connections, concurrent utterances, audio seconds). See [Rate Limits](/docs/api-reference/rate-limits).

## Audio

- [ ] Sample rate and encoding are consistent across producers. See [Audio Input](/docs/realtime/audio-input).
- [ ] Chunk size is tuned for your latency target.
- [ ] Keep-alive silence is sent during long idle periods if needed.

## Observability

- [ ] Server events and error codes are logged for triage. See [Server Events](/docs/api-reference/server-events) and [Errors](/docs/api-reference/errors).
- [ ] You track time-to-stable-text and visible reflow. See [Understanding Latency](/docs/concepts/latency).

## Data

- [ ] You have decided what to persist client-side (typically the final transcript).
- [ ] You have reviewed [Security & Privacy](/docs/production/security-privacy) and [Data Retention](/docs/production/data-retention).
