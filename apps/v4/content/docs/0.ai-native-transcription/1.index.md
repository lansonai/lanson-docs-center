Lanson Live brings context-aware AI refinement into real-time transcription. Every utterance gets an **AI second look** before its completed transcript is delivered. **StableStream™** makes that possible by prioritizing stable, finalized utterances over a stream of constantly changing draft words.

> **AI Review is not the ASR model's built-in language understanding.**
>
> Lanson Live uses a separate language reasoning model to review each transcription candidate against the conversation's context. This happens inside the real-time transcription pipeline, before the completed text is delivered.
>
> The speech recognition model identifies the words. The reasoning model evaluates them. StableStream™ makes it possible to deliver the reviewed result as the first committed transcript.

## Three distinct layers: ASR decoding vs. dedicated LLM reasoning vs. StableStream™

A common misconception is to confuse an ASR model's internal language decoder with real-time AI review. Almost every modern speech-to-text model has some built-in statistical language modeling—but its comprehension, context window, and modality are fundamentally limited compared to a dedicated language reasoning model.

Lanson Live separates real-time transcription into **three distinct architectural layers**:

| Layer | Component | What It Does & Its Boundary |
|---|---|---|
| **Layer 1: Speech Recognition (ASR)** | Acoustic & internal language model | Predicts the most likely candidate words from audio signals, phonetic patterns, hotwords, and a narrow, sound-bound local window. Its context is extremely limited and tied to acoustic frames. |
| **Layer 2: Independent AI Reasoning** | Separate language reasoning model (LLM) | Evaluates the ASR candidate transcript using human-like semantic comprehension across multi-turn conversation history, domain context, and phonetic clues—strictly constrained to faithfully recovering what the speaker actually said. |
| **Layer 3: Real-Time Orchestration** | **StableStream™** & **LiveFinal™** | Establishes the segment boundary that allows **both** the ASR model and the separate reasoning model to complete their work before the first committed transcript is delivered to your application. |

Crucially, **we harness the full semantic comprehension of a dedicated reasoning model, but constrain its task strictly to faithful transcript recovery.** A reasoning model does not lose its reasoning power just because it is not performing intent analysis, task planning, or tool calling—instead, 100% of that reasoning capacity is focused on resolving live speech ambiguity in context.

## The real-time dilemma: paying the price nobody else pays

Correcting a transcript with an LLM *after* a recording finishes is straightforward—an offline pipeline has the entire audio file, full conversational hindsight, and no real-time clock.

The hard problem is: **how do you run a separate language reasoning model on what someone just said while the conversation is still happening?**

In real-time systems, nothing is free. To run a second, dedicated reasoning model inside a live stream, you must pay a structural price that conventional streaming STT APIs refuse to pay: **you must give up unreviewed, word-by-word provisional draft streaming.**

- **Why conventional STT APIs are stuck at Layer 1**: Traditional streaming APIs optimize for emitting the first phonetic token as fast as possible (`partial` events every 100–200ms). Because they push raw ASR decoder guesses across the network before a sentence even has meaning, a separate reasoning model never gets a chance to evaluate the utterance before your application sees it.
- **The price Lanson Live pays—and the reward it unlocks**: Lanson Live deliberately holds speech inside a bounded segment window (**StableStream™**) rather than streaming flickering draft words. Paying that controlled buffering price is what buys the pipeline time and semantic context to run **dedicated LLM review** before emitting a single, finalized result (**LiveFinal™**).

## Why naive LLM post-processing makes live transcripts worse—not better

Even if a developer tries to replicate Layer 2 by piping a conventional STT API's output into an external LLM call, simply adding an unconstrained LLM to live speech fragments frequently makes transcripts **worse**:

1. **Short-window hallucination**: When a live utterance is only 2–4 seconds long, an unconstrained LLM lacks surrounding context and often invents plausible-sounding words that the speaker never said.
2. **Paraphrasing and style drift**: General-purpose LLMs are trained to "improve" prose—smoothing grammar, dropping deliberate repetition, or rewriting the speaker's actual phrasing into generic AI text.
3. **Over-correction of valid speech**: Without tight coupling to ASR phonetic clues, an external LLM will "fix" unusual but accurate phrasing into cliché expressions.
4. **Cross-turn inconsistency**: Evaluating each segment in isolation causes proper nouns and technical terms to be spelled differently from one sentence to the next.

Lanson Live's differentiation is the **end-to-end pipeline discipline** that coordinates the ASR model, cross-turn memory, and the constrained reasoning model inside a single real-time boundary:

| Dimension | Conventional Streaming STT | DIY STT + External LLM Post-Processor | Lanson Live (AI-Native Pipeline) |
|---|---|---|---|
| **Intelligence layer** | Layer 1 only: ASR built-in acoustic/language decoder (tiny, sound-bound context) | Disconnected ASR + unconstrained external LLM | **Dual-model pipeline**: ASR recognition model + dedicated language reasoning model (LLM) |
| **Context perspective** | Local acoustic frames & shallow token transitions | Isolated text string passed to an external prompt | **Human-like semantic context** across rolling multi-turn conversation history |
| **What crosses the wire** | Flickering partial drafts followed by an unreviewed ASR `final` | Two separate outputs (raw STT first, patched LLM rewrite later) | One immutable, LLM-reviewed completed utterance (`LiveFinal™`) |
| **Segment window control** | Fixed acoustic decoder frames | Disconnected from STT segmentation | Scenario-tuned segment duration balancing cadence vs. semantic context depth |
| **AI guardrail philosophy** | None (pure acoustic beam search) | High risk of paraphrasing, hallucination, and grammar rewriting | **Speaker-faithful reasoning**: phonetic + semantic evidence, zero paraphrasing, no-op when accurate |

## Dynamic segment sizing: matching the price to your scenario

Because Lanson Live trades provisional word flicker for a bounded reasoning window, **segment duration becomes a tunable architectural lever**.

Real-time is not one universal latency number—it is a delivery strategy matched to your application's tolerance for latency versus how much intra-segment speech the reasoning model can inspect at once:

- **Shorter segments (`2–4s`)** deliver completed updates more frequently for rapid conversational turn-taking, relying on rolling cross-utterance memory to supply semantic context to the reasoning model.
- **Longer segments (`5–10s` and `12s+`)** give both the ASR model and the reasoning model a wider span of surrounding speech before finalization, maximizing disambiguation accuracy when a few extra seconds of buffering are acceptable.
