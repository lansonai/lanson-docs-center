A live transcript often becomes direct input to an AI agent, retrieval pipeline, workflow engine, or live user interface. Those downstream systems need more than raw recognized words—they need explicit delivery state and sequencing signals.

::ai-native-pillar-visual{pillar="downstream"}
::

## Structured signals for downstream applications

Lanson Live includes structured fields on every completed transcription event so applications can process live speech deterministically:

| Field | Purpose |
|---|---|
| `utterance_index` | Monotonic utterance order within the session so concurrent segments can be sequenced reliably. |
| `text` | The delivered utterance text after in-pipeline review. |
| `raw_text` | Preserves the initial recognition output before optional refinement. |
| `transcript.state` | Delivery lifecycle state (`stable` on completed utterance events). |
| `transcript.correction_applied` | Indicates whether context-aware refinement modified the candidate text. |
| `transcript.safe_for_downstream` | Readiness signal indicating non-empty text without language-detection errors. |

## Delivery state vs. accuracy guarantees

Downstream readiness indicators describe **delivery state and processing signals**, not a guarantee that every recognized word is accurate.

- Gate downstream LLM tool calls or workflow triggers on `transcript.safe_for_downstream === true`.
- Order all incoming utterances by `utterance_index` before appending them to agent memory or conversation history.
