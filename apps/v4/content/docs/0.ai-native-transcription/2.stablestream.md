**StableStream™** is the architectural foundation that makes real-time, dual-model transcription possible. Instead of exposing continuously changing word-by-word acoustic guesses, Lanson Live holds speech until a coherent segment boundary is reached—allowing **both the speech recognition model and the separate language reasoning model** to complete their work before the first committed transcript is delivered.

> **The speech recognition model identifies the words. The reasoning model evaluates them. StableStream™ makes it possible to deliver the reviewed result as the first committed transcript.**

## Why word-by-word draft streaming blocks real-time AI reasoning

In streaming speech recognition, emitting a word 100 milliseconds after a syllable is spoken means emitting it **while only the ASR acoustic decoder has seen it—and before the sentence has semantic meaning**.

Conventional STT engines make that trade-off because they only run **Layer 1 (ASR acoustic/language decoding)**: show a provisional guess immediately, then overwrite it repeatedly as more audio arrives.

If you want **Layer 2 (a separate language reasoning model)** to evaluate the transcript against conversational context *before* your application commits it, word-by-word draft streaming is a dead end:

1. **A reasoning model needs a semantic unit**: While an ASR decoder operates on 20ms audio frames, a language reasoning model operates on semantic meaning. It cannot judge whether a homophone or domain term is right on a two-word fragment whose predicate has not been spoken yet.
2. **Delivering before reasoning defeats the contract**: If you stream unreviewed ASR tokens to the client first and run a reasoning model later, your UI still flickers and your downstream AI agents still ingest unreviewed errors.

StableStream™ deliberately pays the price of holding the utterance inside a bounded segment window so that **ASR recognition + LLM contextual reasoning** both finish *before* the transcript crosses the delivery boundary.

## Segment duration as an architectural lever

Once you use a bounded segment window to run both ASR recognition and LLM reasoning before delivery, **segment duration** becomes the primary lever for matching the pipeline to your scenario's latency tolerance:

| Scenario Profile | Typical Window | How ASR + Reasoning Model Use the Window |
|---|---|---|
| **Voice Interfaces & Turn-Taking** | `2–4s` | Delivers frequent completed utterances for interactive turn-taking; the reasoning model relies heavily on cross-utterance session memory to disambiguate short turns. |
| **Live Conversations & Meetings** | `5–10s` | Gives both the ASR model and the reasoning model full clause/sentence boundaries, balancing responsive captions with rich intra-segment semantic context. |
| **Broadcasts & Caption Feeds** | `12s+` | Buffers multi-clause passages when timing is flexible, giving the reasoning model maximum surrounding speech context before finalization. |
